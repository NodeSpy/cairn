# Kernel feasibility experiments E1, E2, E3, E4, E6

Run on VM `lfs-a` (Arch, kernel **7.2.11-arch1-1**, 2 vCPU, 3.9 GB), btrfs on `/dev/sdb` mounted at
`/cache`, everything under `/cache/exp-hsm/`. Test tool: `experiments/hsm/` (static musl binary, one
binary, subcommands `e1 e2 e3 e4 e6` plus `h-*` helper roles that are re-exec'd as separate
processes so readers, writers and holders are real separate processes). Run as root
(CAP_SYS_ADMIN). Raw outputs are in `docs/experiments/raw/`.

Reproduce: `cargo build --release --target x86_64-unknown-linux-musl` in `experiments/hsm`, copy to
the VM, then `sudo hsm e1`, `sudo hsm e2 /cache/exp-hsm/e2 --long`, `sudo hsm e3 /cache/exp-hsm/e3 500`,
`sudo hsm e4 deterministic`, `sudo hsm e4 <dir> 4000 v0|v1 <widen_us> <rest_us> <readers> <writers> <holders> <label>`,
`sudo hsm e6 /cache/exp-hsm/e6 3`.

Byte pattern for all content checks: `byte(k, off)` never equals 0, so a hole/zero is always
detectable and every byte is verified against the expected value.

## E1. Fill through the event fd

Setup: `ftruncate`-sparse placeholder (0 blocks), `FAN_PRE_ACCESS` inode mark, group
`FAN_CLASS_PRE_CONTENT`, `event_f_flags = O_RDWR`. The handler thread does `pwrite` of the whole file
through the event fd, then `FAN_ALLOW`. The reader is a separate process (`h-read`, and also the real
`/usr/bin/cat`). `inotifywait -m` runs on the directory during each step.

**A. Correctness.** 1 MiB + 777 byte file: reader got 1049353 bytes, FNV matches the expected
pattern, 0 zero bytes. `cat` of a 300000-byte placeholder: byte-for-byte equal. Result: PASS.

**A. Events.** One event per `read()` syscall (64 KiB reads: 18 events for 1 MiB), range present and
page aligned: `(0,65536) (65536,65536) ... (1048576,65536) (1048576,69632)` (the last is the EOF read).
`pread(off=12345,len=100)` gave range `(12288,4096)`. A 1 MiB `pread` gave `(0,1048576)`. The mark
stays after the fill, so a second `cat` of the already-filled file again fires 18 events.

**A. inotify.** During fill+read: `OPEN, ACCESS x17, CLOSE_NOWRITE`. **No `MODIFY`.** Control (a plain
write by another process) showed `CREATE, OPEN, MODIFY, CLOSE_WRITE`, so the monitor works. PASS.
(The `ACCESS` events are the reader's own reads.)

**mtime.** The fill changes mtime to now (1500000000 became 1794547019): restoring is required.

**B. futimens on the event fd (new finding).** The design says "futimens ... still emit
IN_MODIFY/IN_ATTRIB". Measured:

| Call | inotify |
|---|---|
| `futimens` on event fd, atime=UTIME_OMIT, mtime set | **`MODIFY`** (once per call) |
| `futimens` on event fd, atime **and** mtime set | `ATTRIB` |
| same two on a regular fd (control) | `MODIFY` / `ATTRIB` |
| `utimensat(path)`, atime=OMIT, mtime set | `MODIFY` |
| `fchmod` | `ATTRIB` |
| `ftruncate(same size)` | `MODIFY` |

So NONOTIFY does not suppress it, and "mtime only" is reported as `IN_MODIFY` (the kernel maps an
mtime-only change to FS_MODIFY, atime-only to FS_ACCESS, both to FS_ATTRIB). Consequence: the
"restore mtime" step in fill and evict is **not** silent, and with the obvious `UTIME_OMIT` atime it
looks like a content modification to any `IN_MODIFY` watcher. Set both atime and mtime to get
`IN_ATTRIB` instead. mtime restored to 1600000000 correctly in both variants.

**C. FAN_DENY.** `FAN_DENY | (EIO<<24)`: reader got `EIO` (`cat: Input/output error`), 0 bytes, file
still 0 blocks. Plain `FAN_DENY` gives `EPERM`. PASS.

**D. mmap.** `mmap(PROT_READ, MAP_SHARED)` of a 1 MiB placeholder: exactly one event, delivered
**during `mmap()`** (0.03 ms after t0, before it returned) with range `(0,1048576)`; later page
touches generate none; bytes correct. `mmap(off=8192,len=16384)`: range `(8192,16384)`. Partial-fill
check (handler fills only the first 4 KiB): the other 1044480 bytes read as zeros with no further
event, confirming there are no fault-time hooks. Matches §3.1.

**E. O_TRUNC.** `open(O_WRONLY|O_TRUNC)` of a placeholder: **no event** (events in the window before
the first write: 0). Size was 0 right after open. The later 1-byte `pwrite` raised one event with
range `(0,4096)`; the handler saw size 0 and skipped the fill. Matches §3.1.
`truncate(path, 0)`: one event, range `(0,0)`. `truncate(path, 524288)` on a 1 MiB placeholder: one
event, range `(524288, 0)`. **The event is raised before the size changes**, so a naive "size>0 and
blocks==0, fill" handler downloads the whole old 1 MiB file just to truncate it.

E1 verdict: PASS (reader gets right bytes, no IN_MODIFY from fill, DENY/EIO works, mmap and O_TRUNC
as expected).

## E2. Read-lease write gate

Setup: daemon opens `O_RDONLY`, `F_SETSIG(SIGRTMIN+2)`, `F_SETLEASE F_RDLCK`, signal blocked in all
threads, signalfd thread reads `ssi_fd`, sleeps the configured delay, then `F_UNLCK`s that fd. The
write opener is a separate process timing the syscall with `CLOCK_MONOTONIC`.

**Gate with 1000 ms release delay** (blocked time = syscall duration, signal time = from before the
syscall to the daemon reading the signalfd):

| Opener | Blocked | Signal at daemon | Breaks |
|---|---|---|---|
| `open(O_WRONLY)` | 1000.29 ms | 0.026 ms | 1 |
| `open(O_RDWR)` | 1000.37 ms | 0.061 ms | 1 |
| `open(O_WRONLY\|O_APPEND)` | 1000.21 ms | 0.021 ms | 1 |
| `open(O_WRONLY\|O_TRUNC)` | 1000.48 ms | 0.060 ms | 1 |
| `truncate(path, 0)` (syscall) | 1000.23 ms | 0.032 ms | 1 |
| `sh: echo >> f`, `echo > f`, `cp x f` | 1001.8 to 1002.3 ms | 1 break each | 1 |
| `open(O_WRONLY\|O_NONBLOCK)` | **0.013 ms, EAGAIN** | 0.043 ms | 1 |

Gate overhead beyond the artificial delay: 0.2 to 0.5 ms (includes process scheduling of the
helper). `ssi_fd` always equalled the leased fd. After the release the lease is gone (`F_GETLEASE`
= none). Three leased files: opening m1 gave `ssi_fd` = m1's fd only; two concurrent openers on m0
and m2 gave two queued signals with `ssi_fd` 4 and 6 (correct).

**Cases that must not break (all confirmed, 0 breaks, lease still `RDLCK`)**: `open(O_RDONLY)`,
`rename`, `unlink`, `chmod`, `utimensat`, `link`, `rename(tmp, leasedpath)`, and `sed -i` (writes a
temp file, renames over the path). After `sed -i` the path points to a *new* inode while the lease
stays on the old, now unlinked inode (`nlink=0`); the daemon is not told by the lease, only the FID
group sees it.

**Latency with 0 ms release delay (300 iterations each, microseconds, per open syscall)**:

| | p50 | p90 | p99 | max |
|---|---|---|---|---|
| leased `open(O_WRONLY)`, run 1 | 29.6 | 35.8 | 69.0 | 90.4 |
| leased `open(O_WRONLY)`, run 2 | 46.1 | 81.7 | 135.8 | 194.0 |
| unleased baseline, run 1 / run 2 | 5.5 / 6.2 | 7.4 / 20.0 | 18.9 / 39.7 | 98 / 115 |

Added gate cost with an instant daemon: about 25 to 40 µs. Signal reaches the daemon after p50 15 to
20 µs, p99 50 to 85 µs.

**Never released**: `fs.lease-break-time` = 45; the writer unblocked after **46.26 s** and the lease
was removed. Works on btrfs.

E2 verdict: PASS. Findings that need design attention:

1. **`F_SETSIG` is reset when the lease is removed.** Found by accident: after the first lease
   release, re-taking `F_RDLCK` on the same fd without calling `F_SETSIG` again delivered plain
   **SIGIO and killed the process** ("I/O possible"). Re-arm `F_SETSIG` before every `F_SETLEASE`
   that creates a lease (upgrade/downgrade of an existing lease keeps it).
2. **`ssi_fd` is only a fd number.** A break signal can be read after the fd was closed and its
   number reused. Observed: a stale signal for an old fd 4 made the daemon `F_UNLCK` an unrelated
   file's lease that had been given fd 4. Keep a fd to path/inode map, never close a leased fd
   before its pending signals are drained, and `fstat` check ino before unlocking.
3. **`O_NONBLOCK` openers fail with EAGAIN** while a break is pending, but still send the signal.
   Coreutils `truncate -s 0 file` does exactly this and prints "Resource temporarily unavailable";
   same would apply to any tool using `O_NONBLOCK|O_WRONLY`. A retry after the release works.

## E3. Writer detection on placeholders

Setup: placeholders with inode mark; in the handler: fill, then **control probe with the event fd
still open**, then `dup2(/dev/null, eventfd)`, then the real probe (fresh `O_RDONLY` +
`F_SETLEASE F_RDLCK`, released immediately). Holder processes (`h-hold`) keep the file open in
various ways; trigger is an external `cat`-like reader or the holder's own operation.

Control: with the un-neutered event fd the probe is **always EAGAIN** (the O_RDWR event fd is a
writer), confirming `neuter_fd` is required. Results of the neutered probe (last event):

| Holder | Probe | Expected |
|---|---|---|
| none, `O_RDONLY`, `O_PATH` | OK | OK |
| `O_WRONLY` open, `O_RDWR` open (reader trigger) | EAGAIN | EAGAIN |
| `O_RDWR` then read only (self trigger) | EAGAIN | EAGAIN |
| `O_WRONLY\|O_TRUNC` open (external reader; event on the empty file still fires) | EAGAIN | EAGAIN |
| `O_TRUNC` then `pwrite` | EAGAIN | EAGAIN |
| `O_TRUNC` then `ftruncate` extend | EAGAIN | EAGAIN |
| `ftruncate` (shrink 1; same size) on `O_RDWR` | EAGAIN (event fires) | EAGAIN |
| `O_WRONLY` write, then closed (`stale`) | first probe EAGAIN, later probes OK | no stale positive |
| writer opened **before** the mark was added | EAGAIN | EAGAIN |
| `mmap(PROT_WRITE, MAP_SHARED)` with fd open | EAGAIN | EAGAIN |
| `mmap(PROT_WRITE, MAP_SHARED)` **fd closed**, mapping kept | **EAGAIN** (the vma holds the file) | EAGAIN |
| `mmap(PROT_READ, MAP_SHARED)` fd closed | OK | OK |
| `mmap(PROT_READ\|WRITE, MAP_PRIVATE)` fd closed | OK | OK |

Randomized: 500 trials over 10 holder kinds (writer present iff `wronly`, `rdwr`,
`trunc-extend`, `mmapw-closed`): **0 false negatives, 0 false positives, 0 trials without an event**
(per kind: 44 to 55 trials, always the expected answer). Note that `O_RDWR` used only for reading is
reported as a writer (conservative, correct by the "open for write" definition).

**Full placeholder flow (design: keep the lease after a successful probe).** Variant A: handler keeps
`F_RDLCK` and leaves the mark. The reader of a 256 KiB file took **1.2 s** (4 events, each event fd
open breaks the handler's own lease, waiting for the 300 ms release delay each time). A later writer
open blocked 300.3 ms and was signalled (gate works). Variant B: the handler **removes the mark
first**, then takes and keeps `F_RDLCK`: reader took **1.46 ms**, later writer open blocked 300.2 ms
with 1 signal. So marks on a leased file turn every queued event into a lease break.

E3 verdict: PASS, no false negatives found.

## E4. Eviction safety

Setup: 16 files of 256 KiB, each leased by the daemon (`F_RDLCK`), pattern content, mtime fixed per
file. Cycle: *restore* (if holes: self-triggered fill event; `F_RDLCK`; remove mark), random rest,
then the §3 eviction: add mark; `F_WRLCK` upgrade; **(window opens)** `F_UNLCK`; self-trigger a read
(fresh `O_RDONLY` + 1 byte `pread`); the handler punches the whole file through the event fd, restores
mtime (`futimens`), allows. If the upgrade fails: remove the mark, refuse. Breakers handle lease
breaks (delay 0) by unlocking, so writers pass the gate. A single handler thread serializes events.

Variants: **v0** = literally §3 (punch whenever our self event arrives). **v1** = v0 plus: any event
from another process on the victim inode between `F_UNLCK` and the punch sets `aborted`; if aborted
the handler allows but does not punch. `widen_us` = random sleep after `F_UNLCK` (simulates a slow or
descheduled daemon). Readers (separate processes): read(), pread, mmap, mmap-then-close-fd-then-sleep,
open-sleep-read, long hold with repeated preads; all bytes compared. Writers: O_WRONLY/O_RDWR pwrite
of the *correct* pattern, ftruncate, mmap write. 4000 eviction cycles per run.

| Run | Variant | widen/rest µs | Procs (read/write/hold) | Evicted | Refused EAGAIN | Aborted | Reader checks | **Bad reads** | Pre-punch interloper events |
|---|---|---|---|---|---|---|---|---|---|
| C1 | v0 | 0 / 500 | 4 / 0 / 0 | 2974 | 700 | n/a | 8136 | **0** | 1 |
| C2 | v0 | 300 / 300 | 4 / 0 / 0 | 3043 | 634 | n/a | 8192 | **0** | 50 |
| C3 | v0 | 300 / 300 | 3 / 2 / 2 | 2492 | 729 | n/a | 7433 | **126 (all zeros)** | 113 |
| C4 | **v1** | 300 / 300 | 3 / 2 / 2 | 2223 | 780 | 237 | 7439 | **0** | 105 |

Plus 326 to 779 per run of "could not re-lease (writer open)" restore failures. Final full-file
verification after each run: 0 bad files. mtime restored on all 16 files in C1/C2 (no writers); in
C3/C4 writers change mtime legitimately (11 and 13 files differ).

**v0 fails.** First bad bytes: `f1 off=0 got=0 exp=8`, `f1 off=65536 got=0`, `f11 off=0 got=0`. Cause
(not a violation of "HSM mode fixed at open"): a reader that opens after `F_UNLCK` is HSM, its read or
mmap event reaches the handler **before** our self event, the handler allows it (data still present),
then our punch runs while the reader is mid-copy (single 256 KiB `read`) or later touching a mapping
(mmap event allowed at map time, pages touched after the punch read holes, no event). The mark does
not help because the event was already allowed. v1 closes exactly this window and had 0 bad reads
with 105 such events (237 aborts) in the same load. v0 only passes when the mix has few mmap/hold
readers (C1, C2).

**Why the mark-before-upgrade ordering itself is sound.** From the kernel source
(`do_dentry_open`, master): `i_readcount_inc` / `get_write_access` happens before
`fsnotify_open_perm_and_set_mode`, which happens before `break_lease`. Therefore an opener is either
counted before our `F_WRLCK` check (upgrade fails EAGAIN) or decides its HSM mode after the mark
exists. No run showed a non-HSM reader seeing holes: every bad read came from the v0 handler ordering
above.

**Deterministic refusal cases (`raw/E4-deterministic.out`, holder opened BEFORE the mark)**:

| Holder state | Result |
|---|---|
| nobody, fd opened and closed, `O_PATH` fd | evicted (correct) |
| `O_RDONLY` open (never read) | refused EAGAIN, RDLCK intact, mark removed |
| `O_RDWR`, `O_WRONLY` open | refused EAGAIN (lease already broken by the open) |
| `mmap(PROT_READ, MAP_SHARED)` fd closed | refused EAGAIN |
| `mmap(PRIVATE)` fd closed | refused EAGAIN |
| `mmap(PROT_WRITE, SHARED)` fd closed | refused EAGAIN |
| `O_RDONLY` / `O_RDWR` opened AFTER the mark (HSM-mode, no read yet) | refused EAGAIN |

All 11 correct, blocks stayed 512 on every refusal. A failed upgrade leaves a read lease intact.
Consequence: a file that any process keeps open or mapped (even read-only) can never be evicted.

E4 verdict: the §3 sequence **fails** under concurrent readers with mmap/long holds; with the v1
abort rule it **passes** (4 runs x 4000 cycles, 0 bad reads in v1, 0 bad final files).

## E6. Cost of a mark

Setup: 64 MiB hot file and 10000 x 4 KiB files, all filled and in page cache; handler is a separate
process doing the minimum (read batch, `FAN_ALLOW`, close fd). Reader opens the file **after** the
mark exists (HSM-mode fd). 3 s per measurement. Latency: 1 of every 8 `pread`s timed.

| Scenario | 4 KiB pread ops/s | mean / p50 / p99 (ns) | 1 MiB read ops/s (MiB/s) | cat 10k (s, median of 5) | in-proc 10k files (s) |
|---|---|---|---|---|---|
| no marks | 663,836 | 1523 / 1118 / 15771 | 10,560 (10,560) | 0.1023 | 0.0727 |
| inode mark (hot file; 10k marks on the small files) | 28,656 | 35348 / 31327 / 81966 | 7,011 (7,011) | 0.8358 | 0.8720 |
| parent dir mark, `FAN_EVENT_ON_CHILD` | 28,505 | 35075 / 29221 / 86244 | 6,483 | 0.7557 | 0.8356 |
| sb (filesystem) mark | 27,506 | 36562 / 32146 / 88943 | 7,102 | 0.8323 | 0.8557 |
| unrelated inode mark elsewhere | 651,823 | 1551 / 1125 / 15194 | 10,429 | 0.1003 | 0.0780 |
| fd opened before the mark was added | 673,484 | 1510 / 1109 / 15103 | 12,767 | n/a | n/a |

Events: exactly **1 event per `read`/`pread` call**; 10k-file `cat` and the in-process loop raised
**2 events per file** (data read plus the EOF read), so 100000 events for 5 x 10k files.
Handler-limited event rate: 28.7k events/s with one reader, 60k events/s with two reader threads
(inode mark, 4 KiB).

Added latency per event (mean): 4 KiB pread **+33.8 µs** (inode), +33.6 µs (parent), +35.0 µs (sb);
p50 +30 µs. 1 MiB read: +46 µs (inode), +59 µs (parent), +45 µs (sb) on a 96 µs baseline. Small
files: 7.3 µs/file becomes 83 to 87 µs/file, about **+40 µs per event** at 2 events per file. With
the mark in place `cat` of 10k files is **about 8x slower**; a 4 KiB hot read is **about 23x slower**.
Setup of 10001 inode marks took 29.8 ms.

Observations: all three mark kinds cost the same per event (the cost is the event round trip and
context switches, not the mark lookup); a mark on an unrelated inode costs nothing measurable; marks
affect only files opened after the mark exists (the "pre-opened" fd saw no events and full speed, and
1 MiB reads were not slower).

E6 verdict: a mark must be removed once a file is filled and leased (design already says so). The
directory-mark or sb-mark option would put this cost on every read of every child, which is not
acceptable for filled files unless an upstream BPF filter exists.

## Contradictions with DESIGN §3 / §3.1

1. **§3.1 "futimens still emit IN_MODIFY/IN_ATTRIB" / "evicting are silent except the mtime restore
   (IN_ATTRIB)"**: mtime-only `futimens` (atime `UTIME_OMIT`, as in `sys::set_mtime_fd`) emits
   `IN_MODIFY`, also through the NONOTIFY event fd. `IN_ATTRIB` needs both times set.
2. **§3 "Safe eviction" order** is not sufficient on its own: the punch can run after the handler
   already allowed another process's read/mmap event on the same inode (126 zero reads in 7433).
3. **§3.1 "Event fd ... through `break_lease()`"**: confirmed, and worse than the note suggests: a
   marked + read-leased file stalls every queued event for a full break cycle (1.2 s for four events
   at a 300 ms release), and with a handler that does not release it stalls up to 46 s.
4. **§3 "Write gating (placeholders)": "drop the event fd, then try F_RDLCK"** works (E3), but the
   handler must remove the mark before it keeps the lease (variant B).
5. **§3.1 `O_TRUNC`/`truncate`**: `truncate(path, n)` raises its event *before* the size changes;
   range is `(n, 0)`.
6. Not in the design at all: `F_SETSIG` reset on lease removal (SIGIO kills the daemon), stale
   `ssi_fd` after fd reuse, `O_NONBLOCK` opens failing with EAGAIN during a break.

Confirmed as written: HSM mode fixed at open (no non-HSM reader saw holes), mmap event at map time
with a range and no fault-time events, no event at `O_TRUNC`, `FAN_DENY|errno` works, writer opens
and `truncate(path)` break read leases while `rename`/`unlink`/`link`/`chmod`/`utimensat`/`sed -i`
do not, fill and punch through the event fd raise no `IN_MODIFY` themselves, break time 45 s.

## Design changes needed

1. **Eviction handler rule (mandatory).** Keep a per-inode "evicting" record set before `F_UNLCK`.
   Any event from another process on that inode that the handler processes before the punch marks it
   aborted; the self-triggered event then allows without punching, and the file stays filled (remove
   the mark again, re-take the lease). The handler must process events on one thread (or hold a lock
   across record check and punch). Document that a refused or aborted eviction is normal.
2. **mtime restore: set atime and mtime together** (`futimens` with both fields), so the side effect
   is `IN_ATTRIB`; consumers of the local inotify stream (and §6) must treat any `IN_MODIFY`
   reaching them during a fill/evict as possibly caused by our own mtime restore, or avoid
   it by using both times. Update `sys::set_mtime_fd` accordingly.
3. **Fill handler for `truncate`**: when the event range has `count == 0` (truncate), fill only
   `[0, offset)` (nothing when `offset == 0`); do not fetch the whole old content.
4. **Hydrate handler order**: fill, probe (neutered fd), remove the mark, then take and keep
   `F_RDLCK` (re-arming `F_SETSIG` first). Never hold a read lease on a file that is still marked.
   If the probe says EAGAIN, take the server write lease; the mark can still be removed afterwards.
5. **Lease bookkeeping**: re-issue `F_SETSIG(SIGRTMIN+2)` before every `F_SETLEASE F_RDLCK` on an fd
   whose lease was removed (otherwise SIGIO kills the process; also block SIGIO as a safety net).
   Keep an fd to inode/path table, verify `fstat` ino before unlocking on a break signal, and do
   not close a leased fd with signals pending.
6. **Expect EAGAIN to tools using `O_NONBLOCK|O_WRONLY`** (coreutils `truncate`) while a break is
   pending. Keep release latency short (break completes in tens of µs when the daemon is idle) and
   consider an optional retry hint in docs.
7. **Cost model**: budget about 35 to 45 µs per event for any mark type and 1 event per `read()`
   call (plus one for the EOF read). A mark on a file that stays marked makes `cat` of small files
   about 8x slower, so keep marks only on non-resident files; sb and parent marks are not viable for
   filled files. For small files (one read per file) a hydrate event is cheap relative to the fetch.
8. **Eviction is never possible for files held open or mapped** (even `O_RDONLY`, even a closed fd
   with a live mapping): the LRU needs a "pinned" state and should not busy-retry; use the `F_RDLCK`
   upgrade result (EAGAIN) as the pin signal and retry later or on close (FID `CLOSE_*` events).
9. §14.1 criteria: E1, E2, E3 as written pass; E4's criterion ("nobody ever reads holes") passes
   only with change 1; E6 numbers above replace the open question in §3.1's "mark directories
   instead of every placeholder" option: per-event cost is identical, so it only saves mark count,
   not time.
