## Conclusions
- Reflinks work on the vendor 4.4 kernel, so the server's CAS-plus-reflinked
  tree view (DESIGN §5) is viable. Materializing a tree file from the CAS
  costs microseconds.
- Dedup after the fact on the NAS is too slow for bulk use (29 MiB/s). The
  server must **never write duplicate data and dedupe later**. Write new
  content once into the CAS and reflink it into the tree. Block-level
  background dedup on the NAS is out. Partial overlap in large files is
  handled by chunk-level transfer dedup only, and may cost duplicate space
  on the NAS.
- Hashing: one core hashes about 1 GiB/s, which roughly matches 10GbE line
  rate. Verifying uploads on the server is affordable; use a thread pool.
- Writes with fsync reach 265 MiB/s on the array, which caps sustained
  upload throughput. The client write-back queue absorbs bursts.
- Not tested yet: running inside Container Manager (bind-mount and ioctl
  passthrough), and network throughput devbox to NAS.
